# Bring every Bootstrap reference to 5.3.8 (and Bootstrap Icons to 1.13.2)

## Delivery & audit log

| Date | Event |
|---|---|
| 2026-11-07 | Applied in DevCoreApp and authored in `out/`. Not yet delivered. |

## Why

The solution loaded two different Bootstrap versions: Desktop and the `/setup` page used 5.3.8
from jsDelivr, while the Mobile PWA served a vendored 5.3.3 copy from `wwwroot/lib`. 5.3.8 is the
latest stable release (as of 2026-11-07; `6.0.0-alpha.1` is the only newer build and is
deliberately **not** adopted). 5.3.4–5.3.8 are patch releases: bug fixes only, so no markup or
class changes are needed.

## Current state (DevCoreApp before this change)

| Surface | How Bootstrap is loaded | Version |
|---|---|---|
| Client.Desktop `wwwroot/index.html` | jsDelivr CDN, CSS + `bootstrap.bundle.min.js`, with SRI | 5.3.8 |
| Client.Desktop `wwwroot/index.html` | jsDelivr CDN, `bootstrap-icons.min.css` | Icons 1.13.1 |
| Server.Api `Core/Pages/_Layout.cshtml` (`/setup`, `/Error`) | jsDelivr CDN, CSS only, with SRI | 5.3.8 |
| Client.Mobile `wwwroot/index.html` | local `lib/bootstrap/dist/css/bootstrap.min.css` | 5.3.3 |

Mobile vendors the files rather than using the CDN on purpose: it is a PWA, and the service worker
caches local assets for offline use. Keep it local.

## Proposed change

1. **Mobile: replace the vendored files.** Get the official 5.3.8 package and copy its `dist/`
   over Mobile's. Same 32 CSS and 12 JS file names as 5.3.3, so `index.html` does not change.

   ```bash
   curl -sSL -o bs.tgz https://registry.npmjs.org/bootstrap/-/bootstrap-5.3.8.tgz
   tar -xzf bs.tgz            # → package/dist/{css,js}
   cp package/dist/css/* src/Client/<Mobile project>/wwwroot/lib/bootstrap/dist/css/
   cp package/dist/js/*  src/Client/<Mobile project>/wwwroot/lib/bootstrap/dist/js/
   ```

   Do this in a scratch directory outside the repo; only the copied files should end up in the diff.

2. **Desktop: bump Bootstrap Icons** in `wwwroot/index.html`:

   ```html
   <link href="https://cdn.jsdelivr.net/npm/bootstrap-icons@1.13.2/font/bootstrap-icons.min.css" rel="stylesheet">
   ```

   (No `integrity` attribute: the existing link had none.)

3. **Desktop + Server.Api: confirm 5.3.8.** In DevCoreApp these already read:

   ```html
   <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet"
         integrity="sha384-sRIl4kxILFvY47J16cr9ZwB07vP4J8+LH7qKQnuqkuIAvNWLzeN8tE5YBujZqJLB" crossorigin="anonymous">
   <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js"
           integrity="sha384-FKyoEForCGlyvwx9Hj09JcYn3nv7wiPVlz7YYwJrWVcXK/BmnVDxM+D2scQbITxI" crossorigin="anonymous"></script>
   ```

   If a fork is on an older version, replace both the URL **and** the `integrity` hash. A URL change
   with a stale hash makes the browser refuse the file, and the page loads with no styles and no modals.

## Affected shared surface

- `Client.Mobile` `wwwroot/lib/bootstrap/dist/css/*` and `dist/js/*`. These are vendored third-party
  files. A fork should not fence them; if it has patched them, it should move the patch into its own
  stylesheet first.
- `Client.Desktop` `wwwroot/index.html`. This is a root shell file and may hold `project-specific`
  fences (extra stylesheets, a product title). Change only the Bootstrap and Icons lines.
- `Server.Api` `Core/Pages/_Layout.cshtml`. Check only.

A fork with no Mobile client (or one that loads Bootstrap from the CDN there) skips step 1.

## Verification

- `head -c 120 …/wwwroot/lib/bootstrap/dist/css/bootstrap.min.css` and
  `…/dist/js/bootstrap.bundle.min.js` both show `v5.3.8`.
- `grep -rn "bootstrap@\|bootstrap-icons@" src --include=*.html --include=*.cshtml` (excluding
  `bin/obj`) shows only `bootstrap@5.3.8` and `bootstrap-icons@1.13.2`.
- `dotnet build <solution>.slnx` has 0 errors.
- Manual: open Desktop `/`, `/mobile` and `/setup` (on an empty database) with DevTools open. Check
  that the console has no SRI or 404 errors, that a Desktop modal opens and closes
  (`showBootstrapModal`/`dismissBootstrapModal` in `Scripts/app.ts`), and that icons render. On
  Mobile, do a hard reload so the service worker picks up the new assets.
